## Part 2 — The Fix Process (Reusable)

### The 8-Step Cycle

Every fix follows this exact sequence:
TEST — Run the command. Record baseline (time, output).

DIAGNOSE — Read the handler. Find the error. Understand the cause.

FIX — Minimal change to ONE file. No other edits.

VERIFY — Get-Content the file. Confirm the change is on disk.

RESTART — Ctrl+C server, python a2a_server.py, wait for warm.

RE-TEST — Same command. Confirm fix works. Compare to baseline.

DIFF — git diff. Confirm only intended change.

COMMIT — git add <file>; git commit -m "..."; git push.

text

### Critical Rules

- **One file per fix.** Never edit two files in one commit.
- **One change per fix.** Don't add "while I'm here" improvements.
- **Test before commit.** If it doesn't work, revert (`git checkout <file>`).
- **Verify on disk before restarting.** If the file wasn't saved, you're testing old code.
- **Never batch-fix.** Multiple files edited at once = untrackable failures.
- **Never trust `git diff` empty = no change.** The change may be already committed.

Part 3 — Traps Discovered This Session
Trap 1: Duplicate methods
rustypycraw had two _gather_context methods. Python uses the last one.
The first is dead code — but the first is where the initialization was
placed. So initialization was dead code.

Check: (Select-String -Path <file> -Pattern "def methodname").Count — should be 1.

Trap 2: Init after return
Initialization placed after a return statement never executes. Check
__init__ for scanner/analyzer/parser setup. If missing, commands that
need them will AttributeError.

Trap 3: Mixed indentation silently changes flow
draftclaw had an except block where the return was at a different
indentation level than the log_err. Python accepted it — but the return
was outside the except, running on success where e was unbound.

Check: $lines = Get-Content <file>; $lines[N..M] | ForEach-Object { "len=$($_.Length): $_" } — inconsistent lengths reveal misalignment.

Trap 4: Facade blocks
14 of 21 agents have 30+ try/except: pass imports in the handler that
look like constitutional compliance but enforce nothing. They don't break
anything, but they're not doing anything either.

Impact: Cosmetic. Article VII (no silent failure) violations.
Priority: Low. Remove only after functional bugs are fixed.

Trap 5: smart_ask exists but is underused
BaseAgent.smart_ask() implements retrieval + memory + LLM + truth
resolution + conflict detection. Only txclaw uses it explicitly.
Other agents use ask_llm directly or have domain-specific grounding.

This is OK. Not every command needs smart_ask. lawclaw /law has
its own grounding (CourtListener + authority ranking). mediclaw /diagnose
has its own (NIH/CDC citations + pro/patient prompts).

Trap: Don't assume missing smart_ask = broken. Test output quality first.

Trap 6: Command grounding is per-command
Each commands/*.py has its own approach:

/law → grounded synthesis with "use ONLY these authorities"

/diagnose → professional vs. patient prompt selection

/create → deterministic template fill (no LLM at all)

/scan → deterministic file scan (no LLM at all)

/blueprint → deterministic drawing (no LLM at all)

Trap: Don't assume "add truth resolution to every command." Each
command needs what its domain needs.

Trap 7: Docs lag code
Docs claim 448MB Chronicle (actually 587 MB), llama-3.3-70b-versatile
(actually openai/gpt-oss-20b), June 5, 2026 (four months old).

Rule: Trust the code and the test results, not the docs. When in doubt,
run the command and see what happens.

Trap 8: git diff empty ≠ no changes
The change may be already committed. Check git log --oneline -5 -- <file>
to see recent commits. This happened with lawclaw — the truth resolution
block was already there from a v3.2.0 commit.

Trap 9: Server doesn't reload on file changes
After editing any .py file, you MUST restart the server. Python caches
bytecode and loaded modules. Edits don't take effect until restart.

Check: Server startup message should say Mem0 Memory: ACTIVE (warm).
If it says anything else, restart failed.
